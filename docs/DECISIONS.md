# Architecture Decision Records (ADR Log)

Chronological log of key decisions. Newest decisions appended at the bottom.

| # | Decision | Rationale |
|---|---|---|
| 1 | Backend is Python + FastAPI only (no Node hybrid for v1) | Native OpenAPI, strong for parsing/LLM/data; single runtime simplifies deploy/auth/testing. Modular so a worker can split later. |
| 2 | Frontend: React + Vite + `@ui5/webcomponents-react` | Authentic SAP Fiori look (T.11) with React productivity. |
| 3 | Auth: Keycloak (OIDC) with RBAC (Owner/Editor/Viewer) | Standard, SSO-ready; multi-user requirement. |
| 4 | Keycloak shares the same PostgreSQL instance (separate schema) | One DB container; simpler ops. |
| 5 | Events: transactional outbox table only (CloudEvents 1.0); broker optional/future | Minimum viable per user choice; guarantees data/event consistency. |
| 6 | mnemonic IDs immutable; prefix change affects only NEW records | Preserves referential stability (A.1). |
| 7 | Per-prefix configurable pad width in `id_sequence` | Supports TRN 10-digit vs PRT 5-digit (A.2). |
| 8 | Cross-currency transfers store both leg amounts + derived fx_rate | Correct multi-currency accounting (A.4). |
| 9 | Investment current value = latest `valuation_history` row (cache field allowed) | Single source of truth (A.5). |
| 10 | SQL reporting: read-only role, timeout, forced LIMIT, views only, no DDL/DML | Security for free-form SQL (6.2/A.6). |
| 11 | T.9 confirmation enforced at UI only; APIs use prepare/commit for destructive bulk ops | Keeps APIs clean/automatable (A.7). |
| 12 | CloudEvents emitted only for state-changing operations | Avoids read noise (A.8). |
| 13 | Configurable holiday calendars for business-day recurrence rules | Supports "last working day" (A.9). |
| 14 | Document provenance stores original filename + server storage key (not client full path) | Browser cannot obtain client full path (A.10). |
| 15 | Expense item fulfilled by multiple transactions; `expense_item_seq_no` auto-assigned but editable | Matches A.11 semantics. |
| 16 | Category inheritance = Policy 1: item-linked transactions inherit item's category; no category-split when item-linked | Integrity between transaction & item category (D.a). |
| 17 | Income & expense unified in one `cash_flow_item` table with `flow_type` flag | Reuses recurrence/budget logic; supports projections. |
| 18 | `integration_endpoint` is a single registry for all non-LLM integrations (FX/stock/crypto/SMTP) | Canonical, swappable interfaces (T.4.2). |
| 19 | LLM Gateway: central provider list, per-feature primary/secondary, disable switches, master switch, PII redaction, graceful placeholders | T.4.1 requirements. |
| 20 | Notifications: in-app always; email when SMTP configured | User choice; graceful degradation. |
| 21 | Soft delete for financial records; audit_log with before/after; correlation to CloudEvent id | Auditability & recoverability. |
| 22 | Commit continuously; attempt push to remote; if push fails, keep committing locally | User instruction. |
| 23 | All enumerated value sets are configurable entities (`code_list` + `code_value`); every former enum column becomes a `*_cv_id` FK to `code_value` constrained to a specific `list_key` | Drives value helps/comboboxes and server-side validation; lets users extend value sets. System lists seeded with predefined values. Structural `level` fields excepted. |
| 24 | Bundle a local **Ollama** container as a default, configurable LLM provider (kind=ollama) | Out-of-the-box, privacy-friendly, offline-capable local LLM; seeded as an `llm_provider` the Gateway can use as primary/secondary. Model pulled on demand; GPU optional. |
| 25 | Every list screen + `GET /api/v1/{entity}` supports free-text search, structured filters, sort, pagination (Fiori FilterBar; `pg_trgm` indexes) | Users can search/filter transactions, partners, beneficiaries, categories, etc. (spec 6.1 + user request). |
| 26 | `currency_rate` uses validity periods (`begin_date`/`end_date`), lookup `begin_date <= date < end_date`; open-ended entry uses `9999-12-31`; overlaps prevented by GiST exclusion constraint | User-requested; guarantees a valid rate always exists; replaces closest-date approach. |
| 27 | Reporting currency is configurable, **default USD** (`app_config.default_base_currency=USD`, per-user `app_user.base_currency`); transactions stay in native currency (mostly AED). Imports always land on the validation screen for user review/entry before recording | Reports (cash position, projection, net worth, volumes) roll up in USD via validity-period FX; user confirms/edits parsed statement rows before commit (spec 3.2). |
| 28 | `institution` is a configurable entity with a **`country` FK** (also a configurable ISO entity); `account.institution` free-text replaced by `account.institution_id` FK; `institution_type` added as a code list | User request; consistent value help/validation, country grouping, and reporting by institution/country. |
| 29 | Full **data export to XLSX**: single multi-tab workbook (download) or one file per entity written to a server folder | User request; covers config + master + transactional data. Browser cannot pick a client folder, so single-workbook download is the primary UX; folder mode targets a mounted server volume. |
| 30 | Add **DB admin GUI** dev utilities: **Adminer** (`:8081`) plus the existing MinIO console (`:9001`) for object storage | User request; convenient admin access to the databases in dev. Dev-only utilities (not intended for production exposure). (pgAdmin was included initially but removed to reduce image footprint; Adminer covers dev needs.) |
| 31 | **Round-trip import** from an export workbook (`POST /api/v1/import/xlsx`): destructive wipe-and-reload of every entity, preserving original UUID PKs | Enables porting content into a clean instance. Feasible because export preserves UUID keys and portable value encodings. Load runs in one transaction with constraints deferred (self-ref/circular FKs: beneficiary/expense_category parent, transaction↔transfer_group); cells are coerced back to column types (UUID/date/Decimal/JSON), `""`→NULL; Decimals reconstructed via `Decimal(str(...))` to avoid float artifacts. Delete order is the reverse of insert order. UI requires an explicit confirm step. |
| 32 | Frontend uses a **metadata-driven CRUD layer** (`entities.js` + reusable `EntityManager`/`EntityForm`/`ComboField`/`ConfirmDialog`) giving every master/config/transactional entity create/view/edit/delete with autocomplete value help; **every state-changing action requires an explicit confirmation dialog** (extends ADR #11/#T.9 to all UI writes) | Avoids per-entity form duplication; consistent Fiori UX; satisfies universal confirm-on-write requirement. |
| 33 | **Transaction splits API** (`GET/POST/PATCH/DELETE /api/v1/transactions/{id}/splits`): split amounts must sum exactly to the transaction amount; sets `is_split=true`; disallowed when the transaction is linked to a `cash_flow_item` (Policy 1, ADR #16) | Enables multi-category splitting from the UI; enforces integrity server-side. |
| 34 | **Code-value (and code-list) admin API** (`POST/PATCH/DELETE /api/v1/code-lists/{key}/values`): create/edit/deactivate values, honoring `code_list.is_system` and `allow_user_values` guards (system-locked lists reject user edits) | Config data must be maintainable from the UI (ADR #23) while protecting seeded system lists. |
| 35 | **Partner gains `country_id`** (FK country); import mapping will match/create suppliers with country awareness | User request; consistent value help + country-based reporting/mapping for partners. |
| 36 | **Loan gains a configurable `loan_category`** code list (`loan_category_cv_id` FK to code_value: mortgage/personal/car/student/business/other) | User request; classify loans for reporting. |
| 37 | **Structured list filters**: every list screen has a filter bar (`FilterBar` + per-entity `filterFields`); `build_crud_router` accepts declared `filter_fields` as exact-match query params (extends ADR #25 beyond search to structured filters on generic entities) | User request; transactions already had rich filters, now all lists do. |
| 38 | **Refined confirmation model** (supersedes the create/edit-confirm part of ADR #32): **no confirmation on Save**; confirm on **Cancel only when the form is dirty**, on **Delete**, and on **complex/destructive actions** (import commit, import cancel) | User request; reduces friction while still guarding data loss and destructive ops. |
| 39 | **Additive schema convergence at startup**: `bootstrap._apply_additive_columns()` runs idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` for new nullable columns, so existing databases gain new columns without a destructive reset (create_all/initial migration only create tables) | Avoids losing data on dev volumes when models evolve; complements the Alembic-preferred flow. |
| 40 | **Frontend routing via HashRouter**; confirm dialogs are rendered as **siblings** (never nested inside another Dialog, which blocked clicks) | Reliability fixes found during UX testing (Phase 11). |
| 41 | **UI framework migrated from UI5 Web Components to MUI (Material UI, Community/MIT)** with a finance-blue theme (supersedes ADR #2). Lists use MUI **DataGrid** (built-in column filters/sort/pagination); value help uses MUI **Autocomplete** (type-ahead); dates use MUI **X Date Pickers**; charts use **Recharts**. Metadata-driven CRUD layer (`entities.js` + `EntityManager`/`EntityForm`/`ComboField`/`ConfirmDialog`/`SplitEditor`/`FilterBar`/`CodeValueManager`) re-implemented on MUI | UI5 v1/v2 API churn and unfriendly comboboxes; MUI Community is free (only MUI X Pro/Premium is paid, not used) and speeds up admin-style CRUD. |
| 42 | **Audit `_snapshot()` is JSON-safe** (coerces Decimal→float, UUID/date→str) | Writing Numeric columns to `audit_log` JSONB raised HTTP 500 on Account/CashFlowItem/CurrencyRate create. |
| 43 | **Hierarchical `level` is derived server-side** (`parent.level+1`, else 1; depth guard beneficiary 2 / expense_category 3; self/cycle rejected) via a `pre_write` hook on the CRUD factory; the manual Level field is removed from forms | User feedback: level should follow the parent automatically, not be entered. |
| 44 | **Full ISO seed data** (`iso_data.py`: ISO 4217 currencies + ISO 3166-1 countries) replaces the small starter lists | User request for complete currency/country lists. |
| 45 | **Startup init is serialized with a Postgres advisory lock** (API + worker) and new nullable columns are added idempotently (`ADD COLUMN IF NOT EXISTS`) | Concurrent seeding across containers caused duplicate-key races / backend exit 3; existing dev DBs must gain new columns without reset. |
| 46 | **Cash-flow-item → transaction via an item action** (not a field on the transaction form): the transaction form no longer has a `cash_flow_item_id` field; instead a per-row "Create transaction" action on Cash Flow Items materializes a transaction (`POST /v1/recurring/materialize`) that inherits the item's category and is non-split (Policy 1). Standalone transactions keep free category + splits | User request; removes the confusing category/split conflict from the transaction form and makes the item→transaction link explicit. |
